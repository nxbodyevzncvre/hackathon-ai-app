# AUTOPILOT — product brief (transcribed from project kickoff, 2026-11-07)

## 0. How work proceeds

- Stack fixed: Swift 6, SwiftUI, SwiftData, async/await, URLSession. iOS 17.0 minimum. No third-party packages. No Combine. No UIKit unless SwiftUI has no equivalent. No storyboards.
- `docs/BRIEF.md` (this file) holds the brief. Working rules and build commands in `AGENTS.md`. Assumptions in `docs/DECISIONS.md`, one line each.
- One milestone at a time. After each: compiles, launches in simulator, report what changed + what could not be verified.
- Never commit secrets. API keys live in the backend proxy only, and in local `.env` files that are gitignored.
- Files under 250 lines. Split by feature, not by layer. No `Utils.swift` dumps.
- Ambiguity: pick the simplest option that still demos well, record the assumption. Max 5 questions in total, in one batch, at the end of Phase A.
- No placeholder text ("Lorem", "TODO") or dead buttons in anything the demo touches. Unfinished surfaces get an honest empty state.

Build/check commands:
```
xcodebuild -scheme Autopilot -destination 'platform=iOS Simulator,name=iPhone 16' build
xcodebuild -scheme Autopilot -destination 'platform=iOS Simulator,name=iPhone 16' test
```

Output style: concrete, tables over prose, no motivational filler. Technical choices state the reason in one sentence.

## 1. Product

**Name:** AUTOPILOT. **Tagline:** Less thinking about what to do. More time to actually live.
**One-liner:** Tell it what is going on in your life in plain language, and it turns that into organized, scheduled, confirmed actions.

**Core:** unstructured human input → structured, trustworthy actions with one confirmation step.
**Audience (MVP):** university students and early-career professionals, 18–30, one timezone each, heavy messaging and coursework, already using Reminders or Notes but abandoning them.

**Jobs to be done**
1. "I got a message with three things I must do and I do not want to retype them."
2. "I have a vague pile of commitments and no idea what to do today."
3. "I forget things until they are late."

**Non-goals (MVP):** team collaboration, calendar sync, email ingestion, screenshots/OCR, shared lists, web app, widgets, watch app, iPad layout, localization beyond English.

## 3. Navigation

Three tabs plus one persistent action.

```
TabView
├── Today      (default)   plan, overdue, briefing card
├── Inbox                  all tasks, grouped, unsorted first
└── Settings               hours, capacity, notifications, account
Persistent bottom-right capture button, opens CaptureSheet over any tab
```

- No Projects screen. Category chip row as a filter inside Inbox.
- No separate Life Overview screen. Weekly numbers as a compact strip at the top of Inbox.
- No separate Calendar screen. Dates appear as sections, not a month grid.

**Primary journey**
1. Cold start, Today shows an empty state with one primary button: "Tell AUTOPILOT what is happening".
2. Capture sheet opens, user types or dictates, taps Parse.
3. Loading state with skeleton rows, then a Confirm sheet listing proposed actions as cards.
4. Each card shows title, category, due, priority, estimate, plus a confidence chip when below 0.8. Fields are editable inline.
5. User unchecks anything wrong, taps "Add 3 actions".
6. Tasks appear in Today with a short confirmation haptic and a toast with Undo.
7. Next launch shows the daily briefing line at the top of Today.

## 5. Architecture

```
Autopilot/
├── App/            AutopilotApp, RootView, AppEnvironment
├── DesignSystem/   Tokens, components
├── Features/
│   ├── Today/      TodayView, TodayViewModel, PlanBuilder
│   ├── Inbox/      InboxView, InboxViewModel, TaskDetailView
│   ├── Capture/    CaptureView, CaptureViewModel, ConfirmSheet, ConfirmViewModel
│   └── Settings/   SettingsView, SettingsViewModel
├── Domain/         Action, ActionKind, Priority, DueDate, ReminderRule, Category
├── Data/           SwiftData models, ActionRepository, SettingsStore
├── Services/       ExtractionService (protocol + Live + Stub), PlanService, NotificationService, DateResolver, Deduplicator, Haptics
└── Resources/      Assets, Localizable.xcstrings
```

- `@Observable` view models, one per screen, injected via `@Environment`. No singletons except `NotificationService`.
- Repository is the only thing that touches SwiftData. Views never see `@Model` objects, they see `Action` value types.
- Every service has a `Stub` implementation with fixed fixtures. The demo must run fully offline against stubs.
- All errors are typed (`ExtractionError.rateLimited`, `.invalidResponse`, `.offline`) and mapped to human copy. No raw error strings in the UI.
- Strict concurrency on. UI mutation on `@MainActor`. Network and parsing off the main actor.

## 6. Data model

```swift
enum ActionKind: String, Codable { case task, event, reminder, note, payment }
enum Priority: Int, Codable { case low = 0, normal = 1, high = 2 }
enum ActionStatus: String, Codable { case inbox, planned, done, cancelled }

struct DueDate: Codable, Hashable {
  var date: Date          // date component only
  var time: Date?         // optional time component
  var precision: Precision // .day, .time, .unknown
  var isExplicit: Bool    // false means "no date was stated"
  enum Precision: String, Codable { case day, time, unknown }
}

struct ReminderRule: Codable, Hashable {
  var offsets: [TimeInterval] // relative to due, e.g. -86400, -3600
  var isEnabled: Bool
}

struct Action: Identifiable, Hashable {
  var id: UUID
  var title: String
  var notes: String
  var kind: ActionKind
  var category: String      // free string, suggested by AI, normalized to a fixed list
  var priority: Priority
  var due: DueDate?
  var status: ActionStatus
  var estimateMinutes: Int?
  var reminder: ReminderRule
  var sourceQuote: String   // exact fragment of user input that produced this
  var confidence: Double    // 0...1
  var createdAt: Date
  var completedAt: Date?
}
```

- SwiftData: `ActionRecord`, same fields, `id` unique attribute. `due` as three columns (`dueDate`, `dueTime`, `duePrecision`, `dueIsExplicit`) so queries and sorts work. `SchemaMigrationPlan` stub with version 1 only. No CloudKit sync in the MVP.
- Settings: `workdayStart`, `workdayEnd`, `dailyCapacityMinutes` (default 180), `briefingTime` (default 08:00), `notificationsEnabled`, `quietHours` (default 22:00–08:00), `timeZone` from device.

## 7. AI pipeline

Two stages, strictly separated. Deterministic code never guesses, and the model never decides what gets saved.

**Stage 1, normalize input (local, deterministic)**: trim, collapse whitespace, cap at 2000 chars. Attach context: current ISO timestamp, user time zone identifier, locale, weekday names in the user's language, 5 most recent open action titles (duplicate hints only).

**Stage 2, extract (server proxy)**: strict JSON schema output, only validated JSON returned. The app never sees raw model text. Re-validate on arrival: required fields, `due.date` parseable, `confidence` in range, `sourceQuote` substring of input. Any failure → `.invalidResponse` and a retry, never a silent partial save. Anything the model is unsure about becomes a clarification, not an action.

**Extraction prompt rules**
- Extract every distinct actionable item, one action per item. Do not merge two obligations.
- Never invent a deadline. No date stated → `due` null, `precision` unknown.
- Resolve relative dates against the supplied timestamp/time zone, return absolute ISO dates.
- Date without a time → date only, `precision: "day"`.
- Confidence below 0.7 when ambiguous, plus a matching clarification.
- `sourceQuote` copied verbatim.
- `category` ∈ university, work, personal, health, finance, admin, other.
- `estimateMinutes` rough or null. No fabricated precision.
- Output nothing outside the schema.

**Post-processing in Swift**
- Clamp past dates: more than 12h in the past (unless the text said "overdue"/"yesterday") → drop the date, add a clarification.
- Reject `estimateMinutes` outside 5...480.
- Default reminders for explicit deadlines: 24h and 1h before if due >26h away, else 1h before only.
- Duplicate detection: lowercase, strip punctuation, title token overlap >0.7 AND same category AND due within 24h → possible duplicate chip, default unchecked.

**Never:** auto-save without confirmation, silently modify existing actions, invent tasks to fill the plan, or send user text anywhere except the configured proxy.

## 8. JSON schemas

Schemas (extraction request/response, task edit, plan request/response, plan validation and algorithm) as specified: `strict: true`, `additionalProperties: false`, all fields required, nullability via `["string","null"]`; extraction response maxItems 12 actions / 3 clarifications; `orderedIds` validated as a permutation of candidate ids, otherwise fall back to deterministic order.

**Planning algorithm (pure Swift, no AI)**
1. Candidates: status != done, due within next 7 days or already overdue.
2. Sort: overdue first, then priority desc, then due asc, then estimateMinutes asc.
3. Capacity = `dailyCapacityMinutes` minus 30 minutes buffer.
4. Greedy fill in sorted order, skipping any action whose estimate exceeds remaining capacity; record skipped ids.
5. Result carries `capacityUsed`, `skipped`, and a one-line rationale (model or template fallback).

## 9. Backend proxy

One stateless endpoint layer. The iOS app never holds an LLM key.

- Runtime: Cloudflare Worker in TypeScript (fallback: single Vercel Edge function). One file, no framework.
- Endpoints: `POST /v1/extract`, `POST /v1/task-edit`, `POST /v1/plan`, `GET /health`.
- Auth: `Authorization: Bearer <deviceToken>`; token generated on first launch, stored in Keychain, validated via allowlist or per-token daily counter in KV.
- Limits: 60 requests/device/day, 20/hour; `429` with `retryAfter`.
- Validation: body must match schema; reject >2000 chars of input.
- Model call: strict JSON schema, `temperature: 0.2`, 20s timeout, one retry on malformed output, then `502`.
- Config: `LLM_MODEL` and provider key are Worker secrets. Never hardcode a model id in the app or repo.
- Logging: request id, device hash, latency, token counts, error code. Never log user text.
- Responses: `{ "ok": true, "data": {...} }` or `{ "ok": false, "error": { "code": "...", "message": "..." } }`.

## 10. Notifications

- Request permission only after the first successful capture, with a one-line in-app reason first.
- Types: due reminder, daily briefing, overdue nudge. Nothing else in the MVP.
- Defaults: 24h and 1h before a deadline; briefing at `briefingTime`; overdue nudge at 18:00 for actions due today and still open.
- Hard caps: max 3 per day per device, never inside quiet hours, never a nudge for something created in the last 2 hours.
- Every notification opens the relevant action or Today, with a stable identifier per action plus offset so rescheduling cancels the old one.
- Reschedule on every foreground, any task mutation, and any settings change.
- Degrade honestly: permission denied → dismissible row in Today explaining reminders are off, deep link to Settings.

## 11. Privacy and security

- No analytics SDK, no crash reporter, no ad identifiers, no ATT prompt.
- ATS on, no exceptions. No HTTP endpoints.
- Device token in Keychain. No user accounts in the MVP, no email collection.
- Data stays on device in SwiftData; only capture text + minimal context go to the proxy.
- "Delete all data" in Settings wipes SwiftData, pending notifications, and the device token.
- Short privacy note in Settings: what leaves the device, why, no server-side retention of text.
- App Store review stance: AI output always requires user confirmation; no medical, legal, or financial advice claims.

## 12. Monetization (stub only in MVP)

- Free: 10 captures/day, 30 open actions, daily briefing.
- Pro: unlimited captures and actions, plan rationale, reschedule suggestions. €4.99 monthly, €39.99 yearly with 7-day trial.
- Paywall surface + StoreKit 2 entitlement check behind a protocol; `StubEntitlementService` returns Pro in debug. No full purchase flow before the demo.
- Paywall copy states the free limits plainly. No fake countdowns, no dark patterns.

## 13. Milestones

Each milestone ends with: build passes, tests pass, simulator launch verified, one-paragraph report of what is real vs stubbed.

- **M0 Shell and design system.** Xcode project, iOS 17 target, three tabs, tokens, all base components, empty states. DoD: every screen reachable, no placeholder copy.
- **M1 Data layer.** SwiftData models, repository, value types, 8 realistic fixtures behind a debug flag, Inbox list with grouping and filters, task detail with edit and delete. DoD: create, edit, complete, delete survive relaunch.
- **M2 Capture, offline.** Capture sheet, local heuristic parser for a small phrase set, confirm sheet with editable action cards, persistence, toast with undo. DoD: the exact demo sentence produces three editable cards with no network.
- **M3 Real extraction.** Worker proxy deployed, `ExtractionService.Live`, schema validation, retry and error states, clarification chips. DoD: same sentence returns valid structured actions; forced 500 shows the retry state, no crash.
- **M4 Planning and briefing.** Deterministic `PlanBuilder`, Today plan sections, overdue section, briefing card, notification scheduling with caps and quiet hours. DoD: plan respects capacity, notifications fire in the simulator at a test time.
- **M5 Polish.** Dynamic Type, dark mode, VoiceOver labels, haptics, skeleton and error states, Reduce Motion, accessibility audit notes. DoD: no truncated text at XXXL, no contrast failures in either theme.
- **M6 Demo readiness.** Stub fallback verified with airplane mode on, TestFlight build, demo script rehearsed, known-issues list written.

## 14. Demo script

90 seconds, one device, airplane mode off.

1. "This is my whole week." Type: `Tomorrow I need to email my professor about the exam, Friday I have to pay my internet bill, and next week I need to finish my university project.` Tap Parse.
2. Confirm sheet: three cards — university task due tomorrow, finance payment due Friday with a reminder, project due next week with a low-confidence chip.
3. "Nothing is saved until I say so." Uncheck the project, tap "Add 2 actions".
4. Today shows the plan with capacity usage; overdue section explains one item from yesterday.
5. Tap the professor action, say or type "move this to Thursday and remind me the day before", show the updated card.
6. Complete one action, show toast and weekly progress strip.
7. Close on the daily briefing line and the Settings privacy note.

Never demo more. Rehearse three times.
